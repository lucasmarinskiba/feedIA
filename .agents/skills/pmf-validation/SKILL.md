# PMF Validation (Cross-Book Framework)

**Core**: Product-market fit = intersection of customer need (mom test) + feasible build (lean MVP) + hedgehog focus (clear why) + learning loop (measure) + expectations alignment (psychology).

## Components

### 1. 6-STEP LEAN PROCESS (Olsen — Lean Product Playbook)

1. **Determine Target Customer** — Specific persona. Not "everyone."
2. **Identify Underserved Needs** — Importance vs Satisfaction matrix. What do they want but can't get?
3. **Define Value Prop** — "We help [customer] achieve [benefit]" vs [alternative]. Strategy = saying no.
4. **Specify MVP** — Minimum to test hypothesis. User stories. ROI prioritization.
5. **Create Prototype** — Low fidelity OK (sketches, mockups). Match fidelity to test type.
6. **Test with Customers** — 5-8 users per round. Open questions first. Target customers, not friends.

**Loop**: Repeat rounds. Retention = kingpin metric.

### 2. BUILD-MEASURE-LEARN (Ries — Lean Startup)

- **Build**: MVP aligned with hypothesis. Small. Fast.
- **Measure**: Actionable metrics (cohort retention, funnel conversion). Not vanity (total users).
- **Learn**: What changed? Why? Pivot or persevere?
- **Pivot Types**: Zoom-in (focus feature), Zoom-out (broader problem), Customer segment, Customer need, Platform, Business model.

**Principle**: Validated learning > assumptions. Data > gut.

### 3. MOM TEST (Fitzpatrick — The Mom Test)

**Don't ask**: "Is my idea good?" (invites lying).
**Do ask**: Behavior questions.

- "What's the hardest part?" (uncovers real pain)
- "How are you solving this now?" (learn current workflow)
- "When was the last time...?" (specific past behavior)
- "How much would you pay?" (commitment signal)

**Commitment signals** = Real interest:

- Explicit (meet again, buy).
- Monetary (prepay, freemium → paid).
- Effort (introduce, help, refer).

**Anti-pattern**: Asking friends (they lie). Asking for feedback (not data).

### 4. EXPECTATIONS SHAPE PERCEPTION (Ariely — Predictably Irrational)

- Expensive wine tastes better (same wine, different price).
- Price = quality signal.
- Expectations literal (brain processes differently).

**Application**:

- Set expectations early (premium tier first).
- Communicate value upfront (anchors perception).
- Price signals quality (don't underprice MVP).

### 5. HEDGEHOG CONCEPT (Collins — Good to Great)

**3 Circles**:

1. What you deeply understand + can be best at.
2. What drives your economic engine.
3. What you're passionate about.

**Intersection = Hedgehog** = Focus.

**Application to PMF**: Don't try everything. Find ONE clear focus (hedgehog). Organize around it. Say no to everything else.

## Example Build

**Scenario**: Indie founder building a task-management app for ADHD users.

1. **Hedgehog** (Collins):
   - Understand: Built productivity tool myself. ADHD diagnosis. 5 years dev.
   - Economic: $50/month × 500 users = $300K/year (sustainable).
   - Passionate: ADHD community, personal story.
   - Focus: "ADHD-friendly task management." Not generic productivity. Not for everyone.

2. **Define Target** (Olsen):
   - NOT: "Everyone overwhelmed."
   - YES: "ADHD women 25-40, working remote, frustrated with existing tools."

3. **Mom Test** (Fitzpatrick):
   - Ask: "What's the hardest part of your current task app?" (not "do you like task apps?")
   - Learn: "Notifications overload. Too many features. Can't focus."
   - Commitment: "I'd pay $50/month if it solved this."
   - Signal: Specific price (not "maybe," not "I don't know").

4. **Identify Needs** (Olsen):
   - Importance: "ADHD-specific workflows" (9/10).
   - Satisfaction: "Existing tools" (3/10).
   - Gap = opportunity.

5. **Value Prop** (Olsen):
   - "We help ADHD users focus via distraction-free task management."
   - vs "Asana" (too complex), vs "Todoist" (generic), vs "paper" (disorganized).
   - Strategy = NO to: notifications, teams, integrations (v1).

6. **Specify MVP** (Olsen + Ries):
   - User story: "As ADHD user, I want to add 3-5 tasks daily without overwhelm."
   - MVP features: Add task, 3 priority levels, daily focus mode (no notifications).
   - ROI: Priority 1 = focus mode (solves #1 pain). Priority 2 = priority levels. No integrations (Priority 0).

7. **Prototype** (Olsen):
   - Fidelity: Figma mockups (qualitative test = learn why).
   - Test: "Would you use this instead of Asana?" (uncover workflow gaps).

8. **Set Expectations** (Ariely):
   - Show $99/month "Pro" tier (anchor high).
   - Reveal $50/month "Starter" (seems reasonable).
   - Free 14-day trial (loss aversion).

9. **Test** (Olsen + Fitzpatrick):
   - 8 ADHD users. Open: "Walk me through how you'd use this." (observe workflow)
   - Specific: "When would you use focus mode?" (past behavior, not hypothetical).
   - Commitment: "Would you beta test for 2 weeks?" (explicit).

10. **Measure** (Ries):
    - Actionable: Cohort retention (%) at day 3, 7, 14, 30.
    - Cohort analysis: Which feature most used? When churn happens?
    - NOT: "100 signups" (vanity). YES: "7 of 8 users active day 14" (retention 87.5%).

11. **Learn & Pivot** (Ries):
    - Data: 87% retention day 14. Focus mode used 9x/day. Priority levels ignored.
    - Insight: Focus mode = core value. Priority levels = nice-to-have.
    - Hypothesis: "Remove priority levels. Double down on focus mode."
    - Next round: Test with 8 more users. Same metrics.

12. **PMF Indicators** (Olsen):
    - Retention 80%+ day 30 (users come back).
    - NPS 50+ (customers recommend).
    - Churn reason: "Switching to paid" (not "didn't need it").
    - Founder not in loop (users self-onboard, ask in Slack).
